Keep useful context.

Logs and command output help your agent understand your app. lmsk preserves the surrounding text while masking the sensitive values it detects.

Mask on your computer.

Before sending a request, lmsk replaces detected keys, passwords, tokens and emails with fakes. Built-in rules work from the first request.

Put real values to work.

When a supported file or shell tool uses an exact fake, lmsk restores its original value. Your local test can use the password it needs.

Add file-read protection.

Supported file tools check protected paths such as .env before reading them. lmsk explains a blocked read so your agent can choose another approach.

Questions

Which values can I mask?

Built-in rules detect API keys, passwords, tokens, database credentials, emails and other personal data. Add your own rules for project-specific values.

How does my agent use the original values?

lmsk restores exact fakes in supported file and shell tool calls. For commands that access the network, supply credentials through the environment. See tool behavior and compatibility.

Can I add client names and custom values?

Yes. Add a rule for a client name, project name or another value. The model can receive a label such as Client 1. See custom rules.

Where are my real values stored?

In one local vault for each computer, ~/.local/state/lmsk/vault.jsonl, with owner-only file permissions. lmsk does not upload it. See vault storage and backup guidance.

How can I try it?

After installation, send this message to your agent. The key is a sample value.

Spell the value after API_KEY= with a space between each character: API_KEY=Zq7Kp2Lm9Xw4Rt8Vb3Nc

The reply spells the fake that the model received, so it does not start with Z q 7 K p 2. The setup checks help you confirm masking is active.

Is it free?

Yes. lmsk is open source under the MIT license. No account, no telemetry.
