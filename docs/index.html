Real keys for your agent. Fakes for the model.

lmsk swaps API keys, passwords, tokens and emails for fakes before Claude Code or pi sends a request.

Tool calls get the real values back, so your commands still run.

Install

npm install -g @hugolopes45/lmsk

Then connect your agent

Claude Code (preview): type lmsk claude in place of claude.

pi: run pi install npm:@hugolopes45/lmsk, then /reload.

More agents are planned.

How it works

How it works

1

Install it once.

lmsk runs on your computer, as a local proxy in front of your agent or as an extension inside it.

No account, no configuration, no telemetry.

2

Each request is masked on your computer.

lmsk replaces each secret in the request with a fake. It keeps each real value in a vault on your computer.

Each secret arrives as a fake of the same length. The same value gets the same fake for the whole session.

sent: X8fumIJWTm5Rl6C305
3

Tool calls get the real values back.

When the agent writes a file or runs a command with a fake, lmsk puts the real value back. The command runs with your real secret.

run with: Tr0ub4dor-Horse-42

The replies that you read can show fakes.

Questions

Questions

Does it break my commands?
No. The built-in file and shell tools get the real values back before they run. Other tools, such as MCP tools, get fakes.
What if detection misses something?
Then that value goes to the provider. You can add your own rules for the values that you must hide.
Does it slow requests?
A little. Masking runs on your computer, with no network call.
Where are the real values stored?
In a local vault on your computer. lmsk sends the vault nowhere.
How do I stop Claude Code from sending my API keys and .env values to the model?
Run Claude Code with lmsk claude. lmsk masks the secrets in each request before it leaves your computer, also in the text that you paste and in command output. It also refuses the tool calls that open .env, keys and other secret files. A Read deny rule in the Claude Code settings stops a file read, but it does not mask what you paste or what a command prints. In pi, install the extension.
How is it different from gitleaks or a redaction hook?
gitleaks finds secrets in files and commits, so that you can remove them. lmsk uses the gitleaks default rules, and its own rules, on each request that the agent sends. A hook that replaces a secret with [REDACTED] gives that tag to your commands. lmsk gives a fake of the same length to the model, and the real value to the tool calls.
Which agents does it work with?
Claude Code and pi today. More agents are planned.

Technical details are on GitHub.

What still crosses

  • A reply can show fakes. lmsk puts real values back only into tool calls.
  • Your code. lmsk hides secrets, personal data and IDs, not code.
  • The length of each value. A fake has the same length as its real value.
  • It is not a sandbox. A command that the agent runs gets the real values it needs. Use a sandbox as well.
  • This is an early version. Test it on your own data before you trust it. What lmsk does not protect.
